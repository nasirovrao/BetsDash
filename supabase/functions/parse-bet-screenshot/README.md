# parse-bet-screenshot — деплой

Supabase Edge Function, распознающая скриншот купона ставки через Anthropic
API (Claude, vision) и отдающая структурированный JSON для автозаполнения
формы "Добавить ставку" на `app.html`. Ключ модели живёт только здесь, на
сервере — во фронтенде его нет и быть не должно.

## Без CLI, прямо в браузере (то, чем реально пользовались при первом деплое)

Необязательно ставить Supabase CLI — всё ниже можно сделать в Dashboard:

1. **Functions → Deploy a new function → Via Editor** (или открыть уже
   существующую функцию → вкладка **Code**, если это обновление, а не
   первый деплой) — вставить код `index.ts` целиком, заменив то, что было,
   и нажать **Deploy function**.
2. **Project Settings → Edge Functions → Secrets** (или отдельный пункт
   **Secrets** в меню) — добавить `ANTHROPIC_API_KEY` со значением ключа из
   консоли Anthropic (console.anthropic.com → API Keys). Значение при
   повторном открытии всегда маскируется — это нормально.
3. На вкладке **Settings** самой функции — убедиться, что переключатель
   **Verify JWT with legacy secret** включён (по умолчанию так и есть) —
   значит функцию может дёргать только залогиненный пользователь проекта.

Шаги через CLI ниже — альтернативный путь, если он уже привычнее.

## Шаги

1. Установи Supabase CLI, если ещё нет:
   ```
   npm install -g supabase
   ```
2. Залогинься и привяжи локальную копию к своему проекту:
   ```
   supabase login
   supabase link --project-ref <твой-project-ref>
   ```
   `project-ref` — в Supabase Dashboard → Settings → General → Reference ID.
3. Возьми ключ модели в консоли Anthropic (console.anthropic.com → API
   Keys, нужна привязанная карта/оплата — вызовы с картинкой не бесплатны)
   и положи его секретом функции (НЕ в `.env` фронтенда, НЕ в git):
   ```
   supabase secrets set ANTHROPIC_API_KEY=sk-ant-...
   ```
4. Задеплой саму функцию:
   ```
   supabase functions deploy parse-bet-screenshot
   ```
   По умолчанию Supabase проверяет JWT входящего запроса — оставь как есть
   (не добавляй `--no-verify-jwt`), иначе функцию сможет дёргать кто угодно
   без логина, а не только твои пользователи.
5. Проверь, что модель в `index.ts` (константа `DEFAULT_MODEL`) актуальна —
   список vision-моделей меняется, сверься с
   https://docs.claude.com/en/docs/about-claude/models на момент деплоя.
   Можно сменить модель без передеплоя кода — секретом:
   ```
   supabase secrets set ANTHROPIC_MODEL=claude-...
   ```

## Проверка после деплоя

На `app.html` (залогинившись как обычно) нажми "📷 Заполнить по
скриншоту" под заголовком формы, выбери реальный скриншот купона —
поля должны заполниться, появится баннер с уровнем уверенности. Если
вместо этого статус показывает ошибку — текст ошибки обычно указывает
на причину (не задан секрет, неверный ключ, лимит модели и т.п.).

## Лимит: 100 распознаваний в месяц на пользователя (31.08.2026)

Защита от неограниченных расходов — считается каждый ВЫЗОВ функции с
картинкой, не количество ставок внутри одного скриншота (очередь из 3 ставок
с одного скрина по-прежнему стоит "1"). Реализация — новая таблица
`public.screenshot_parse_usage` (`schema_milestone25.sql`, обязательно
прогнать перед деплоем этой версии функции, отдельная миграция от
`schema_milestone24.sql`), одна строка на пользователя на календарный месяц
(`month` — `YYYY-MM`, UTC), пишется исключительно самой функцией через
автоматически доступный `SUPABASE_SERVICE_ROLE_KEY` (RLS явно не даёт
insert/update обычным пользователям — только select своей строки).

Пользователь узнаётся из JWT запроса (`sub` claim, декодируется вручную —
подпись отдельно не перепроверяется, потому что платформенный тумблер
"Verify JWT with legacy secret" уже сделал это до вызова кода функции).

При превышении лимита — HTTP 429 с текстом на русском ("лимит на этот месяц
исчерпан…") и телом `{ usage: { count, limit, remaining: 0 } }`, ключ Anthropic
при этом НЕ дёргается (проверка лимита — до платного вызова, не после).
Успешный ответ тоже несёт `usage: { count, limit, remaining }` — фронтенд
(`app.html`) показывает текущий остаток рядом с кнопкой после каждого вызова.

**Фейл-открыто, не фейл-закрыто:** если переменные окружения недоступны, или
запрос/upsert к таблице usage сам упал (например, миграция ещё не прогнана и
таблицы физически нет) — функция логирует ошибку через `console.error`, но
ПРОПУСКАЕТ пользователя дальше, а не блокирует распознавание. Осознанный
выбор: сбой инфраструктуры лимита не должен положить основную фичу, лимит —
это защита от расходов, а не что-то, ради чего стоит рисковать доступностью.

Известное упрощение (см. также комментарий в `schema_milestone25.sql`):
проверка-и-инкремент — не одна атомарная SQL-транзакция, а последовательные
SELECT и upsert из кода функции. Теоретическая гонка при двух одновременных
запросах от одного пользователя ровно на границе лимита — для одиночного
пользователя, кликающего вручную, риск практически нулевой.

## Тестирование без реального ключа

В `/home/claude/app_test8/supabase-client.js` (тестовое зеркало с mock
Supabase) есть детерминированный мок этой функции — управляется
`sessionStorage.__mock_parse_screenshot_scenario__`
(`success_single` / `success_express` / `low_confidence` / `success_multi` /
`not_detected` / `legacy_flat_shape` / `limit_exceeded` / `error`).
`success_multi` — три ставки с одного скриншота, для проверки очереди
(баннер "N из M", кнопки "Пропустить" и "Прервать очередь", автопереход к
следующей после реального сохранения). `legacy_flat_shape` — эмулирует
недодеплоенную старую версию функции (плоский объект без `bets`), проверяет
клиентский fallback с предупреждением "передеплой…". `limit_exceeded` —
эмулирует ответ 429 при исчерпанном месячном лимите, проверяет текст ошибки
и то, что форма остаётся пустой (ничего не подставляется). Регрессионный
тест — `test_parse_screenshot.py` (общие сценарии) и
`test_screenshot_limit.py` (лимит и отображение остатка). Мок проверяет
только клиентскую логику заполнения формы (она получает тот же формат
JSON, что описан схемой `record_bet_data` в `index.ts`), не сам вызов
Anthropic — это можно проверить только после реального деплоя, ключ
модели в песочнице недоступен.
